# 커밋 규칙

## 메시지

`<type>: <한국어 요약>`

| type      | 용도                    | 예                                           |
| --------- | ----------------------- | -------------------------------------------- |
| `content` | 글 추가·수정, 태그      | `content: 프론트엔드 환경변수 글 이관`       |
| `style`   | `custom.scss` 등 스타일 | `style: 헤딩 상단 마진 추가`                 |
| `feat`    | 플러그인·기능 추가      | `feat: 본문 날짜 뱃지 추가`                  |
| `chore`   | 설정·도메인·README 등   | `chore: 도메인 변경으로 설정 및 readme 갱신` |

## 원칙

- 글(`content`)과 스타일(`style`) 변경은 커밋을 나눈다.
- 작업이 끝나면 커밋·push까지 진행해도 된다. 커밋 전에 커밋 단위와 메시지를 짧게 알린다.
- `main`에 push하면 바로 배포된다. 이미지가 필요한 글은 R2 업로드를 먼저 끝낸다.
- 사용자가 VS Code 등에서 git 작업 중이면(`COMMIT_EDITMSG` 대기 등) 끝날 때까지 git 명령을 실행하지 않는다.
