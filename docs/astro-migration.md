# Quartz → Astro 이사 계획

> 작성: 2026-11-28 · 상태: 계획

## 왜 옮기나

- Quartz는 기능을 플러그인 저장소에서 빌드할 때마다 받아 온다. `quartz.lock.json`의 커밋 고정도 무시돼서, upstream이 바뀌면 사이트가 조용히 깨진다. 실제로 2026-11-26 테마 저장소 구조가 바뀌어 테마 없이 배포됐다. 지금은 `plugins/quartz-themes`에 고정해 막아 둔 상태다.
- `custom.scss`의 상당 부분이 things 테마를 덮어쓰는 코드다(`:root:root:root`). 내 디자인을 직접 쓰는 게 아니라 남의 테마와 싸우는 중이다.
- 목표는 "이 공간을 내 입맛대로 가꾸기"다. 오노추나 /now 같은 실험을 붙일 때 Quartz 구조에 끼워 맞추지 않아도 되게 한다.

## 그대로 가져갈 것 (하지 않는 것)

- 글 작성 방식: Obsidian에서 `content/`에 쓴다. `content/` 폴더와 `.obsidian/`은 건드리지 않는다.
- 배포: GitHub `main`에 push하면 Cloudflare Pages가 배포한다. 도메인과 R2 이미지도 그대로다.
- `functions/api/song.js`(오노추 API)와 Spotify Secret: Cloudflare Pages Functions라서 프레임워크와 상관없이 그대로 동작한다.
- 글 주소: 바꾸지 않는다. 아래 [주소 유지](#주소-유지) 참고.

## 레포지토리 운영

**같은 레포를 유지한다.** 새 레포를 만들 필요가 없다.

| 항목      | 방법                                                                                                                  |
| --------- | --------------------------------------------------------------------------------------------------------------------- |
| 작업 장소 | `migrate/astro` 브랜치. `main`은 이사 끝까지 Quartz로 계속 배포한다                                                   |
| 미리보기  | Cloudflare Pages는 `main` 외 브랜치를 자동으로 미리보기 배포한다 → `migrate-astro.hyemin-jardin.pages.dev`            |
| 히스토리  | 레포 하나에 그대로 남는다. 시작 전에 `git tag quartz-final`로 돌아갈 지점을 표시한다                                  |
| 전환      | `migrate/astro` 브랜치를 `main`에 머지하면 끝                                                                         |
| 되돌리기  | Cloudflare 대시보드에서 이전 배포로 롤백(즉시), 또는 머지 커밋 revert                                                 |
| 정리      | 전환 후 `upstream` 리모트(`jackyzha0/quartz`) 삭제, `quartz/`·`quartz.config.yaml`·`quartz.lock.json`·`plugins/` 삭제 |

### 미리 처리할 것

1. **빌드 출력 폴더** — 확인 완료 (2026-11-28: 빌드 명령 `npm run build`, 출력 `public`, 자동 배포 켜짐)
   - Cloudflare 빌드 설정(빌드 명령, 출력 폴더)은 브랜치 공통이고 출력 폴더는 `public`이다. Astro에서 `public/`은 정적 파일 **입력** 폴더라 이름이 겹친다.
   - 운영 설정을 건드리지 않도록 Astro 쪽에서 맞춘다: `astro.config`에 `outDir: "public"`, `publicDir: "static"`.
   - 빌드 명령이 `npm run build`가 아니라 `npx quartz build`처럼 Quartz를 직접 부르고 있다면, 브랜치에서 빌드가 실패한다. 이 경우 대시보드에서 `npm run build`로 바꾼다(`main`도 같은 결과라 영향 없음).
   - 전환 후 원하면 출력 폴더를 `dist`로 바꾸고 기본 이름으로 되돌린다.
2. **미리보기 주소 리다이렉트** — 확인 완료 (2026-11-28)
   - Bulk Redirect는 `hyemin-jardin.pages.dev`만 잡는다. 배포별 주소(`<해시>.hyemin-jardin.pages.dev`)는 200으로 열린다 → 브랜치 미리보기도 그대로 열린다.
3. **미리보기용 Spotify Secret**
   - 지금 Secret은 Production 환경에만 있다. 미리보기에서도 오노추를 보려면 Preview 환경에도 넣는다. 안 넣으면 위젯이 숨겨질 뿐 다른 문제는 없다.

## 기능 목록

지금 사이트에서 실제로 쓰는 것만 추렸다. 글 9개 기준이다.

### 마크다운

| 기능                                              | 현재 사용                 | Astro에서                                                                                                               |
| ------------------------------------------------- | ------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `[[위키링크]]`, `[[글\|별칭]]`                    | 6곳                       | `remark-wiki-link` 계열 또는 직접 구현. 파일 이름으로 글을 찾아 실제 주소로 바꾼다. 못 찾은 링크는 빌드 실패로 처리한다 |
| 한 줄 줄바꿈 = `<br>`                             | 전체 (`hard-line-breaks`) | `remark-breaks`. **빠뜨리면 문단이 다 붙어 버린다**                                                                     |
| callout `> [!info]`                               | 2곳                       | `rehype-callouts` 또는 직접 구현. 이관 안내 callout 모양 유지                                                           |

| 코드 하이라이트, 언어 라벨, 줄번호(6줄 이상)      | 다수                      | Astro 기본 Shiki + transformer                                                                                          |

## 주소 유지

- 지금 주소는 Quartz 규칙으로 만들어진다. 파일 이름을 소문자로 바꾸고, 공백은 `-`, `?` 같은 기호는 제거한다.
  - 예: `Streaming SSR.md` → `/streaming-ssr`, `React.lazy는 300ms 느리다?.md` → `/react.lazy는-300ms-느리다`
- Astro에서 같은 규칙의 slug 함수를 만든다.
- 현재 주소 21개와 `/index.xml`, `/sitemap.xml`을 `docs/urls.txt`에 저장해 뒀다(전부 200 확인). 이 목록을 Astro 빌드 결과와 하나도 빠짐없이 같은지 비교하는 스크립트로 검증한다.

## 스타일

- things 테마 의존을 끊고 내 스타일시트를 처음부터 쓴다. `custom.scss`의 "이미 정리한 테마 문제"와 "유지하기로 한 결정"(`.claude/rules/styling.md`)이 곧 디자인 명세다.
- 그대로 지킬 결정:
  - `word-break: normal`
  - Safari에서는 `text-wrap: pretty` 쓰지 않음
  - 구분선 `--divider`
  - 모바일 목록 들여쓰기 1.4rem
  - 코드블록 규칙
  - 본문 링크 팝오버 없음
- 테마를 덮어쓸 필요가 없으니 `:root:root:root` 같은 특이도 싸움은 없어진다.
- 레퍼런스: jbee.io (깔끔함), cho.sh (실험적인 요소)

## 단계

| 단계         | 내용                                                                                                   | 끝났다는 기준                                   |
| ------------ | ------------------------------------------------------------------------------------------------------ | ----------------------------------------------- |
| 0. 준비      | `quartz-final` 태그, Cloudflare 빌드 명령 확인, `docs/urls.txt` 저장 (완료)                            | `main` 배포 정상                                |
| 1. 뼈대      | `migrate/astro` 브랜치, Astro 설치, `content/`를 Content Collection으로 읽기, 홈과 글 페이지 최소 버전 | 미리보기 주소에서 모든 글이 열림                |
| 2. 마크다운  | 위키링크, 줄바꿈, callout, 날짜 뱃지, 코드블록                                                         | 9개 글이 지금 사이트와 내용상 같음              |
| 3. 연결      | 백링크, 하단 글 목록, 태그 페이지, 404                                                                 | 위키링크와 백링크가 모두 동작하고 깨진 링크 0개 |
| 4. 부가 기능 | RSS, sitemap, OG 이미지, 검색, 다크 모드, 오노추, 맨 위로                                              | 목록의 기능이 모두 동작                         |
| 5. 스타일    | 스타일시트 새로 작성                                                                                   | PC·모바일(390px)·다크 모드, Chrome·Safari 확인  |
| 6. 검증      | 주소 비교 스크립트, 링크 검사, RSS 검증, Lighthouse                                                    | 차이 0개                                        |
| 7. 전환      | `main`에 머지, 배포 확인, Quartz 파일과 `upstream` 리모트 정리, `CLAUDE.md`·`.claude/rules` 갱신       | 실제 사이트 정상, 롤백 방법 확인                |

1~3단계가 이사의 핵심이다. 여기까지 되면 Quartz 없이도 블로그가 돈다. 4~5단계는 나눠서 해도 된다.
