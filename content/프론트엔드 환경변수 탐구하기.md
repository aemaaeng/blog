### 정의

> 프로그램을 실행할 때 외부에서 주입할 수 있는 key-value 형태의 변수

os 레벨에서 process에 전달된다. 같은 코드라도 환경에 따라 다르게 동작하게 하도록 만드는 것이 목적이다.

### 사용

터미널에서 `printenv` 커맨드로 현재 프로세스에 할당된 환경변수를 확인할 수 있다.

![printenv 실행 결과](https://static.hyemin.dev/images/2026/05/frontend-env-printenv.webp)

실제론 훨씬 더 많은 환경변수가 출력된다.

`export ENV_NAME=value`로 현재 쉘 세션에서만 유효한 환경변수를 임시로 설정할 수 있고, `ENV_NAME=value node server.js` 와 같이 커맨드 앞에 key=value쌍을 붙여 해당 명령 실행 시에만 환경변수를 적용할 수 있다. `package.json`에서 흔히 볼 수 있는 패턴이다.

### .env와 환경변수 참조 라이브러리

매번 위처럼 프로그램 시작 시 환경변수를 일일이 주입하는 것은 번거롭기 때문에 `.env` 파일에 환경변수를 모아두고 실행 환경에 따라 `dotenv`나 `env-cmd` 등의 라이브러리로 로드하는 패턴이 등장하였다.

```bash
# .env
API_KEY=blahblahblah
```

```javascript
// load .dotenv
require("dotenv").config()
console.log(process.env.API_KEY)
```

package.json에서는 환경별 명령어로 다음과 같이 커스텀해 사용할 수 있다.

```json
"build:dev": "env-cmd -f ./env/.dev next build"
```

### 환경변수 참조하기

앞선 예제에서는 `process.env`를 통해 환경변수를 참조했다.
프론트엔드 개발을 하다 보면 프레임워크, 번들러에 따라 저마다의 prefix를 붙여 환경변수를 사용하게 된다.

```javascript
# Node.js
EXAMPLE=key
console.log(process.env.EXAMPLE)

# React
REACT_APP_EXAMPLE=key
console.log(process.env.REACT_APP_EXAMPLE)

# Next.js
NEXT_PUBLIC_EXAMPLE=key
console.log(process.env.NEXT_PUBLIC_EXAMPLE)

# Vite
VITE_EXAMPLE=key
console.log(import.meta.env.VITE_EXAMPLE)
```

왜 환경변수 사용 방식이 저마다 달라 우리를 매번 헷갈리게 하는 걸까?
이는 브라우저에서 환경변수를 참조하는 방식과 이어진다.

### 브라우저에서의 환경변수 참조 방식

브라우저에는 process 객체가 존재하지 않는다. 따라서 `process.env`로 환경변수를 실시간 참조할 수 없다.
우리가 웹에서 보는 퍼블릭 환경변수 값들은 모두 **빌드 시점에 번들러가 문자열로 치환해 JS 번들에 주입한 결과물**이다.

번들러로 하여금 번들에 포함돼도 괜찮은 퍼블릭 환경변수를 구별할 수 있게 하는 수단이 `NEXT_PUBLIC`, `REACT_APP` 같은 prefix이다.

```bash
# Next.js
SECRET_KEY=aaa
NEXT_PUBLIC_API_URL=https://...
```

`NEXT_PUBLIC_API_URL`은 브라우저 번들에 포함되지만, `SECRET_KEY`는 서버 코드에서만 접근 가능하다.
여기서 서버 코드란 브라우저 번들에 포함되지 않는 서버 실행 환경에서 작동하는 코드를 말한다.
ex. API Route, Server Component, Route handler 등..

prefix가 붙지 않은 환경변수는 클라이언트 컴포넌트와 같이 브라우저에 실행되는 코드에서는 참조할 수 없다.
브라우저에는 노출되면 안 되지만 빌드 과정에서는 필요한 값이 있다면 사용 중인 CI/CD 툴로 환경변수를 세팅해 사용할 수 있다.

#### React (Create React App)

```typescript
// packages/react-scripts/config/env.js

// Grab NODE_ENV and REACT_APP_* environment variables and prepare them to be
// injected into the application via DefinePlugin in webpack configuration.
const REACT_APP = /^REACT_APP_/i;

function getClientEnvironment(publicUrl) {
  const raw = Object.keys(process.env)
    .filter(key => REACT_APP.test(key))
    .reduce(
      (env, key) => {
        env[key] = process.env[key];
        return env;
      },
      {
        // Useful for determining whether we’re running in production mode.
        // Most importantly, it switches React into the correct mode.
        NODE_ENV: process.env.NODE_ENV || 'development',
        // Useful for resolving the correct path to static assets in `public`.
        // For example, <img src={process.env.PUBLIC_URL + '/img/logo.png'} />.
        // This should only be used as an escape hatch. Normally you would put
        // images into the `src` and `import` them in code to get their paths.
        PUBLIC_URL: publicUrl,
        // We support configuring the sockjs pathname during development.
        // These settings let a developer run multiple simultaneous projects.
        // They are used as the connection `hostname`, `pathname` and `port`
        // in webpackHotDevClient. They are used as the `sockHost`, `sockPath`
        // and `sockPort` options in webpack-dev-server.
        WDS_SOCKET_HOST: process.env.WDS_SOCKET_HOST,
        WDS_SOCKET_PATH: process.env.WDS_SOCKET_PATH,
        WDS_SOCKET_PORT: process.env.WDS_SOCKET_PORT,
        // Whether or not react-refresh is enabled.
        // It is defined here so it is available in the webpackHotDevClient.
        FAST_REFRESH: process.env.FAST_REFRESH !== 'false',
      }
    );
  // Stringify all values so we can feed into webpack DefinePlugin
  const stringified = {
    'process.env': Object.keys(raw).reduce((env, key) => {
      env[key] = JSON.stringify(raw[key]);
      return env;
    }, {}),
  };

  return { raw, stringified };
```

CRA에서는 `REACT_APP_` prefix가 붙은 환경변수를 번들에 포함하도록 webpack 설정에 기본적으로 세팅해준다.

#### Next.js

초기에는 next.config.js에 번들에 주입할 퍼블릭 환경변수를 명시적으로 맵핑시켰다. (호환성을 위해 관련 설정이 아예 제거되지는 않아 현재에도 사용되고 있다.)

```typescript
// next.config.js
module.exports = {
  env: {
    API_URL: process.env.API_URL,
  },
}
```

이후에는 `NEXT_PUBLIC_` prefix 방식으로 공개 가능한 환경변수를 자동으로 구분짓도록 바뀌었다.

next.config.js env에 맵핑하게 되면 이 값을 js 번들에 노출시키겠다는 뜻이니 민감한 값이 노출되지 않도록 주의해야 한다.

```typescript
/**
 * Collects all environment variables that are using the `NEXT_PUBLIC_` prefix.
 */
export function getNextPublicEnvironmentVariables() {
  const defineEnv: [string, string | undefined][] = []
  for (const key in process.env) {
    if (key.startsWith("NEXT_PUBLIC_")) {
      const value = process.env[key]
      if (value != null) {
        defineEnv.push([`process.env.${key}`, value])
      }
    }
  }
  defineEnv.sort((a, b) => a[0].localeCompare(b[0]))
  return Object.fromEntries(defineEnv)
}

// NEXT_PUBLIC_* prefix가 붙은 환경변수와 config단 환경변수를 수집하여 빌드
export function getStaticEnv(config: NextConfigComplete | NextConfigRuntime, deploymentId: string) {
  const staticEnv: Record<string, string | undefined> = {
    ...getNextPublicEnvironmentVariables(),
    ...getNextConfigEnv(config),
    "process.env.NEXT_DEPLOYMENT_ID": deploymentId,
  }
  return staticEnv
}
```

#### Vite

vite에서는 process 대신 `import.meta.env` 방식을 사용한다.

```typescript
// VITE_로 시작하는 환경변수 추출
export function resolveEnvPrefix({ envPrefix = "VITE_" }: UserConfig): string[] {
  envPrefix = arraify(envPrefix)
  if (envPrefix.includes("")) {
    throw new Error(
      `envPrefix option contains value '', which could lead unexpected exposure of sensitive information.`,
    )
  }
  if (envPrefix.some((prefix) => /\s/.test(prefix))) {
    // eslint-disable-next-line no-console
    console.warn(
      colors.yellow(
        `[vite] Warning: envPrefix option contains values with whitespace, which does not work in practice.`,
      ),
    )
  }
  return envPrefix
}

// packages/vite/src/node/config.ts
// load .env files
// Backward compatibility: set envDir to false when envFile is false
let envDir = config.envFile === false ? false : config.envDir
if (envDir !== false) {
  envDir = config.envDir ? normalizePath(path.resolve(resolvedRoot, config.envDir)) : resolvedRoot

const userEnv = loadEnv(mode, envDir, resolveEnvPrefix(config))

// 생략
```

```typescript
  for (const key in config.env) {
```

### 요약

- 브라우저에는 process 객체가 존재하지 않는다.
- 프론트엔드의 환경변수는 런타임 참조 값이 아니며, 빌드 과정에서 번들러가 문자열로 치환해 주입하는 값이다.
  - 따라서 os 환경변수라기보다는 빌드 설정값에 가까운 개념으로도 볼 수 있다. (추정)
- 퍼블릭 환경변수 구별을 위해 각 도구마다 다른 prefix 체계를 가지고 있다.
- 서버 환경변수는 브라우저에 노출되어서는 안되며, 서버 코드 실행 환경에서만 접근해야 한다.
